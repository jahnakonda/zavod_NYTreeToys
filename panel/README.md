# Панель управления NYTreeToys

Локальный бэкенд (вариант C): веб-панель для запусков ИИ-агентов и отложенной публикации.
Только stdlib Python, состояние — SQLite, сервер слушает `127.0.0.1:8123`.

## Запуск

```
cd work/own/zavod_NYTreeToys
python panel/server.py
```

Открыть: http://127.0.0.1:8123 (агент открывает сам по [[open-site-in-browser]]).

## Возможности

| Кнопка | Что делает | Механика |
|---|---|---|
| «Сделать пост» у карточки | продюсер пишет пост по карточке (writer → editor → фото из источников, без ComfyUI) и сам ставит его в очередь на выбранное время (ВК+ТГ) | headless `claude -p` + автодобавление в очередь (runs.meta) |
| Запустить исследователя | обслуживание базы фабрик (cron-task.md) | headless `claude -p` |
| Обновить сайт | пересборка блога + деплой на GitHub Pages | sync → линк-чекер → push в tmp/nytoys-pages |
| ВК-логин | сохранить сессию vk.ru | panel/publish_vk.py --login |

## Логика панели

- **Выбор карточки для публикации** — главный блок: только неопубликованные карточки
  (research/fabriki/), без постов в очереди (queued-защита от дублей). Одна кнопка
  «Сделать пост»: продюсер пишет пост (writer → editor → фото из источников, без ComfyUI);
  в runs.meta — дефолт «сегодня 18:00, ВК+ТГ» — точные дата/время и площадки задаются
  в очереди.
- **Очередь публикаций** — полностью автоматическая (ручная форма удалена; POST /api/queue
  остался в API). Строки со статусом «сформирован» редактируемые: название карточки, город,
  дата (кнопка с всплывающим календарём, текущий год) и время (список 09:00–22:00),
  чекбоксы ТГ/ВК/Сайт (сайт включён по умолчанию — снимай, если не нужен). Публикация идёт
  в выбранное время сама (draft активируется планировщиком как pending); кнопка
  «Опубликовать сейчас» выпускает немедленно (в течение 20 с). «Проверить» показывает тексты
  (ВК + ТГ-подпись) и картинки поста. «Отложить» (для «сформирован»/«в очереди») переводит
  пост в блок «Отложенные публикации», планировщик его не трогает. «Повторить» — для упавших.
  Опубликованные (done) в очереди не показываются.
- **Параллельные запуски** — панель допускает несколько продюсеров одновременно
  (в «Ход работы» — отдельные карточки). Коммиты сериализует `panel/commit_safe.py`
  (файловый замок): продюсер-задание и задание исследователя предписывают коммитить
  только через него, чтобы не сталкиваться на .git/index.lock. Исследователя лучше
  не запускать параллельно с продюсерами — оба правят research/fabriki.
- **Отложенные публикации** — блок после очереди: отложенные посты (status `deferred`).
  Пост и картинки хранятся — заново формировать не нужно; у карточки кнопка
  «Сформировать пост» остаётся скрытой, чтобы не создать дубль. «Вернуть в очередь»
  возвращает пост в редактирование (draft) с прежними параметрами; если запланированное
  время уже прошло — время переносится на завтра 18:00 во избежание мгновенной публикации.

## Публикация по расписанию

- **ТГ** — `panel/publish_tg.py` (Bot API): подпись ≤1024 зн обязательна, картинки `-tg`-варианты
  из `assets/<пост>/`, фолбэки — все `photos[]` файла, ген-картинки `assets/<пост>-*.<img>`,
  затем просто папка поста (без площадочных вариантов). Без VPN — префлайт getMe валит задачу со
  статусом «не удалось (код 2)» → кнопка «Повторить» с включённым VPN. Автоповторов нет.
- **ВК** — `panel/publish_vk.py` (UI Playwright, профиль `panel/vk-profile`): перед первым
  автопостингом один раз нажать «ВК-логин» и войти в vk.ru в открывшемся окне Edge.
  Сессия сохраняется; если испортится — задача упадёт с кодом 2, повторить логин.
  Загрузка фото: клик «Загрузить с устройства» перехватывается `expect_file_chooser`
  (иначе ВК открывает нативный диалог Windows — окно Проводника, блокирующее страницу);
  кнопка устройства есть в двух видах компостера (дропзона или меню «Ещё»);
  chooser не перехвачен → фолбэк на скрытый input — ТОЛЬКО внутри модалки компостера
  (`posting_modal_box`): инпут вне компостера принадлежит альбому группы и зальёт туда фото.
  Прилипший черновик компостера (недоопубликованный пост с вложениями) меняет вид
  редактора и ломает локаторы — перед публикацией сбрасывается крестом с
  «Выйти без сохранения». Проверка цикла без публикации: `python panel/publish_vk.py
  --post posts/<ф>.json --dry`. Картинки: `-vk`-варианты → все `photos[]` → папка поста
  → ген-файлы. Внимание: вложенные (не опубликованные) фото ВК сохраняет в
  «Основной альбом» группы — при discarded-пробах заливка остаётся в альбоме.
- Порядок площадок в задаче: ТГ затем ВК (как в JSON очереди). Провал одной площадки
  останавливает задачу (вторая не выполняется), статус и хвост лога — в панели.
- «🌐 сайт» в строке очереди = после удачной публикации пересобрать и задеплоить сайт.
- «Исключим ComfyUI»: продюсер берёт фото из источников; в очередь посты попадают
  автоматически — через «Сделать пост» у карточки.

## Сайт и раздел «Опубликованные»

- Раздел «Опубликованные» — посты, попавшие на площадки: до панели — сеяно из журнала
  сессий (PUBLISHED_SEED в server.py), после — панель дописывает сама при удачной задаче.
- Сайт (jahnakonda.github.io/nytoys-site) обновляется ТОЛЬКО по кнопке «Обновить сайт»
  (команда владельца на деплой): sync
  (`tmp/sync_nytoys_blog.py --published`, рендерит только опубликованные — черновики
  не утекают на сайт) → линк-чекер → копия в `tmp/nytoys-pages` (img/ заменяется целиком —
  грабля деплоя 28.10) → коммит+push.

## Файлы

- `server.py` — HTTP + SQLite + планировщик (поток, опрос каждые 20 с)
- `publish_tg.py` / `publish_vk.py` — публикаторы (можно вызвать вручную:
  `python panel/publish_tg.py --post posts/<файл>.json`)
- `producer-task.md` — задание headless-продюсеру ({TOPIC} подставляется)
- `commit_safe.py` — обёртка git add + commit с файловым замком (параллельные агенты)
- `static/index.html` — интерфейс
- `panel.db`, `runs/`, `vk-profile/` — рабочие данные (вне git: база+логи+**куки сессии ВК**)

## Границы

- Сервер — только localhost, наружу не слушает; автопостинг создаётся только владельцем вручную.
- **Ход работы** — блок под шапкой: какой агент что делает прямо сейчас и готовность в %.
  Источник — потоковые события `claude -p --output-format stream-json`: субагенты
  (писатель/редактор/фото), файлы, план шагов. Проценты — эвристика по этапам
  (старт → writer 30 → editor 55 → фото 75 → пост собран 88 → готово 100).
- Если панель перезапустили во время работы агента, при старте он помечает такие запуски
  как упавшие («ПРИОСТАНОВЛЕНО» в логе), а неподтверждённые посты продюсера возвращает
  в «сформирован» — ничего не теряется.
- Если селекторы ВК-редактора изменятся — publish_vk.py упадёт со скриншотом в `runs/`
  (`vk-fail-*.png`), регламент обновить по скиллу NYTreeToys-content.
